<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /episodes/{guid}/{skip,reprocess} | guid is URL path segment; stage is ?stage query param |
| API handler → SQLite | Writes mutate episodes/cascade tables via dedicated per-request connection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | EpisodeStore.reset_episode (table name interpolation in f-string DELETE) | mitigate | STAGE_CASCADE is a closed module-level dict — table names never originate from user input; the only user input is the `from_stage` KEY which is validated against VALID_STAGES at the API layer before reaching the DAO; `# noqa: S608` comment with rationale |
| T-03-03 | Tampering | Concurrent API DB write vs pipeline DB write | mitigate | 409 gate on `run_state.state != "idle"` runs synchronously before opening Database; D-11 ensures no race; per-request connection (D-15) means even if the gate were bypassed, writes would not corrupt the pipeline's connection state |
| T-03-IV | Input Validation | stage query param | mitigate | `stage in VALID_STAGES` check at handler entry; invalid → 422 before any DB access |
| T-03-NF | Information Disclosure | 404 vs 200 distinction for unknown guid | accept | Returning 404 for unknown guid reveals only that the guid is absent — acceptable per Pitfall 5 (REST convention) and SEC-01 deferral |
| T-03-PE | Tampering | Path traversal in {guid} | accept | guid is used only as a parameterized SQL bind variable — never as a filesystem path; aiosqlite parameter binding prevents injection regardless of guid content |
</threat_model>
