## Phase Goal

**As a** local-network operator, **I want to** start, stop, and per-feed-trigger pipeline runs via REST endpoints with strict single-run semantics, **so that** I can drive the whole pipeline from a UI/curl without ever touching the CLI.

<objective>
Implement the run-lifecycle vertical slice: a client can call `POST /api/v1/run`, observe live progress through `GET /api/v1/status` (now backed by live pipeline updates), stop the run gracefully or forcefully via `POST /api/v1/run/stop[?force=true]`, and trigger a single-feed run via `POST /api/v1/feeds/{slug}/run`. Builds directly on the foundation laid in Plan 01.

Purpose: Deliver CTRL-01, CTRL-02, CTRL-03 and complete the live-data half of STAT-01. The Pipeline gains an `asyncio.Event` stop hook and a RunState reference so it can publish progress.

Output: Modified `components/pipeline.py` (constructor + episode loop additions), new handlers + wrapper in `api/routes/control.py`, new `tests/test_pipeline_stop.py`, expanded `tests/test_api_control.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /run, /run/stop, /feeds/{slug}/run | Triggers background pipeline tasks; only URL slug + ?force query param are untrusted input |
| /run/stop?force → asyncio.Task.cancel() | Force stop injects CancelledError mid-await in pipeline coroutines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Denial of Service | _run_pipeline_task lifecycle | mitigate | finally block calls run_state.reset_to_idle() on every exit path (success, exception, cancellation); AppRunner cleanup cancels orphaned tasks at server shutdown |
| T-03-03 | Tampering | Concurrent /run trigger race | mitigate | 409 gate is a synchronous `if run_state.state != "idle"` check executed before asyncio.create_task; single-threaded asyncio prevents TOCTOU between the check and the state mutation |
| T-03-CR | Tampering | CancelledError handling in wrapper | mitigate | `except asyncio.CancelledError: ...; raise` — explicit re-raise after logging, preventing the swallowed-cancel anti-pattern (Pitfall 2) |
| T-03-SR | Input Validation | _resolve_slug for /feeds/{slug}/run | mitigate | Slug is matched against slugify(feed.title) for feeds already validated by Pydantic at config load — no SQL or filesystem path uses the slug; mismatch returns 404 |
</threat_model>
