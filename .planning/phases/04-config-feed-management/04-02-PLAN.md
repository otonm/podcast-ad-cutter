## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → POST /api/v1/feeds | Untrusted JSON crosses into FeedConfig validation and YAML append |
| HTTP client → PATCH /api/v1/feeds/{slug} | Untrusted JSON crosses into partial-merge + FeedConfig validation; title field must be ignored |
| HTTP client → DELETE /api/v1/feeds/{slug} | Slug must be authoritatively matched; min_length=1 invariant must hold |
| API handler → episodes DB | Read-only COUNT query; must use a dedicated per-request connection, never the pipeline's |
| Process → config.yaml | Partial-write risk on crash; concurrent-writer risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Tampering | POST /api/v1/feeds — malformed feed object | mitigate | `FeedConfig.model_validate(payload)` before write; ValidationError → 422 with JSON body; test verifies missing-url case. |
| T-04-08 | Tampering | POST /api/v1/feeds — duplicate title bypass | mitigate | Explicit linear scan over `cfg.feeds` for matching title BEFORE validate/write; 409 on match; test verifies on-disk state unchanged. |
| T-04-09 | Tampering | PATCH /api/v1/feeds/{slug} — title change attempt | mitigate | Explicit `payload.pop("title", None)` per D-11 so client cannot break slug/DB linkage; test verifies on-disk title unchanged when title sent in payload. |
| T-04-10 | Tampering | DELETE /api/v1/feeds/{slug} — emptying the feed list | mitigate | Construct new AppConfig via `model_validate` so `min_length=1` constraint fires; ValidationError → 422; test verifies last-feed delete fails and config unchanged. |
| T-04-11 | Information Disclosure | SQL injection via feed title in COUNT query | mitigate | Always use parameterized query `WHERE podcast = ?` with `(feed.title,)` tuple; never f-string interpolate. Acceptance criteria greps for the parameterized form. |
| T-04-12 | Tampering | DB connection sharing with pipeline | mitigate | Per-request `async with Database(db_path)` (CLAUDE.md hard rule); acceptance criteria asserts one Database context per request. |
| T-04-13 | Tampering | config.yaml write — crash mid-write | mitigate | Reuses `_write_config_sync` (tempfile in same dir + `os.replace`) from Plan 01 pattern; same POSIX atomicity guarantee. |
| T-04-14 | Tampering | Concurrent feed-modifying requests | accept | Single-user local tool (per CONTEXT.md + RESEARCH.md Pitfall 6); `os.replace` atomicity prevents corruption; last writer wins for overlapping changes; no file lock added. |
</threat_model>
