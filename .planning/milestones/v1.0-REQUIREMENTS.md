# Requirements Archive: Podcast Ad Cutter — Web API v1.0

**Archived:** 2026-05-26
**Status:** ✅ All v1 requirements shipped

## v1 Requirements

### Infrastructure

- [x] **INFRA-01**: Server starts in API mode when `--serve` flag is passed to `main.py`; bare invocation still runs pipeline once and exits — Phase 1 ✓
- [x] **INFRA-02**: `GET /api/v1/health` returns 200 with server uptime and version — Phase 1 ✓

### Pipeline Control

- [x] **CTRL-01**: `POST /api/v1/run` triggers a full pipeline run across all configured feeds; returns 409 if a run is already active — Phase 3 ✓
- [x] **CTRL-02**: `POST /api/v1/run/stop` signals the active pipeline run to stop gracefully; returns 409 if nothing is running — Phase 3 ✓
- [x] **CTRL-03**: `POST /api/v1/feeds/{slug}/run` triggers pipeline processing for a specific feed only — Phase 3 ✓
- [x] **CTRL-04**: `POST /api/v1/episodes/{guid}/reprocess` resets DB state for one episode (full reset or from a specified stage) and requeues it for the next run — Phase 3 ✓
- [x] **CTRL-05**: `POST /api/v1/episodes/{guid}/skip` marks an episode as permanently skipped so the pipeline will not process it — Phase 3 ✓

### Progress Streaming

- [x] **EVT-01**: `GET /api/v1/events` streams Server-Sent Events to connected clients; events include: per-episode stage transitions (download → preprocess → transcribe → topic → ad-detect → edit), download/encode percentage, and run-level counters (total/done/failed per feed) — Phase 2 ✓

### Status & Settings

- [x] **STAT-01**: `GET /api/v1/status` returns current pipeline state (idle/running), active feed slug, per-feed episode counts, and run start time — Phase 3 ✓
- [x] **STAT-02**: `GET /api/v1/settings` returns the current config as JSON with all credential fields redacted — Phase 4 ✓
- [x] **STAT-03**: `PATCH /api/v1/settings` validates the merged payload through Pydantic, writes atomically to `config.yaml`, returns 422 on validation failure; changes apply on the next run — Phase 4 ✓

### Feed Management

- [x] **FEED-01**: `GET /api/v1/feeds` returns all configured feeds with slug, URL, and episode count — Phase 4 ✓
- [x] **FEED-02**: `POST /api/v1/feeds` adds a new feed entry to `config.yaml`; validates feed object through Pydantic before writing — Phase 4 ✓
- [x] **FEED-03**: `PATCH /api/v1/feeds/{slug}` updates a feed's URL or per-feed settings; validates before writing — Phase 4 ✓
- [x] **FEED-04**: `DELETE /api/v1/feeds/{slug}` removes a feed from `config.yaml` — Phase 4 ✓

### Log Access

- [x] **LOG-01**: `GET /api/v1/logs` lists all log files (general app log + per-episode logs) with filename, size in bytes, and last-modified timestamp — Phase 6 ✓
- [x] **LOG-02**: `GET /api/v1/logs/{filename}` returns full log file content with optional byte-offset pagination (`?offset=N&limit=N`) — Phase 6 ✓
- [x] **LOG-03**: `GET /api/v1/logs/{filename}/tail` streams new lines via SSE as they are appended to the log file — Phase 6 ✓

### Database Viewer

- [x] **DB-01**: `GET /api/v1/db/episodes` returns the episode list with GUID, feed slug, pipeline state, and timestamps; supports `?offset=N&limit=N` and `?feed={slug}` filter — Phase 5 ✓
- [x] **DB-02**: `GET /api/v1/db/transcriptions/{guid}` returns full transcription text and segments for one episode — Phase 5 ✓
- [x] **DB-03**: `GET /api/v1/db/ads/{guid}` returns detected ad segments, confidence scores, and cut ranges for one episode — Phase 5 ✓
- [x] **DB-04**: `GET /api/v1/db/costs` returns LLM API costs per episode and aggregate totals; supports `?feed={slug}` filter — Phase 5 ✓
